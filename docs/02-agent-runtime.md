# Qoder 桌面版逆向分析（二）：agent 运行时规格

> 依据：`qoder-worker-runtime.obf.mjs`（v1.1.64，33.2MB）经字符串表解密（12,798 条）与 prettier 结构化（41.2MB 可读输出）后的静态分析。

## 1. 运行时身份

agent 运行时以独立 worker 进程形态存在，产品名为 `qodercli`，版本 1.1.64，构建时间 2026-09-25T18:55:20Z，源提交 8928898，构建站点 global，构建环境 prod，目标平台 win32-x64。构建流水线标识为 `aoneci`，构建目录中出现 `/Users/qoder10/aoneci-runner/ci-pipeline-run-76111764-release-worker-runtime/`，可见其产物由内部 CI 打入 Electron 应用中。

运行时会打包 ripgrep（经 `vendor/ripgrep`）、sharp、node-pty、keytar、photon-node、semver、detect-libc 等依赖，即自身具备图片处理、终端交互与凭据存取能力。

## 2. 工具集

在混淆产物中可确认存在的内置工具名：Read、Write、Edit、Bash、Glob、Grep、Task、TodoWrite、WebFetch、WebSearch、NotebookEdit、exit_plan_mode、Memory、Skill。

与 Claude Code 的工具面高度重合，差异点在于 Qoder 额外把记忆与技能提升为一等工具（Memory、Skill），并保留了 `exit_plan_mode` 这一计划模式出口。未发现 MultiEdit、LS、KillShell 的字符串，说明这几个工具在 Qoder 变体中不存在或被重命名。

工具调用消息结构由 `chat.proto` 约定：`Tool` 带 `cache_id`、`type`、`function`（name、description、parameters、strict），调用与返回使用 `ToolCall`（id、call_id、type、function）与 `ChatMessage.tool_call_id`。模型侧返回的 `tool_calls` 为 `google.protobuf.Struct` 列表。

## 3. 提示词与工作流程

字符串表揭示了若干完整的提示词片段，可归纳出 Qoder 的运行协议。

规划流程分为多个 Phase，其中可确认 `Phase 3: Review`，目标是对 Phase 2 产出的计划进行复核并确保与用户意图一致，要求阅读探索阶段识别出的关键文件以加深理解。

记忆系统有三套机制。`Daily Memory Journal` 要求在一次对话产生跨会话有用的信息后写入当日记忆条目。`Dream: Memory Consolidation` 是一次“做梦”式的反思过程，对持久记忆文件做合成整理，使后续会话更有效。`Memory Review` 先产出按动作类型分组的变更提案，要求不直接落地改动，而是提交给用户批准。记忆类型中包含“指向外部系统信息位置”的记忆（描述在何处查找最新信息），并给出示例场景：重构类改动用户偏好合并为单个 PR、鉴权中间件重写源于合规要求等。

技能系统方面，存在 `skill-creator`、`agent-creator`、`sdk`、`hook-config`、`security-scan` 等内置技能包，每个技能以 SKILL.md 形式给出说明，并有 `notifications/roots/list_changed` 等 MCP 通知处理逻辑。

工具面管理由斜杠命令承担：`/mcp` 列出当前服务器与状态，重启 MCP 会用新工具面；`/loop --max-turns` 控制动态循环轮次上限。`/loop` 机制依赖 `.qoder/loop.md` 文件，该文件内容会在首次触发以及文件变化时自动注入上下文。

## 4. 上下文与压缩策略

字符串中有一组与压缩失败相关的错误码：COMPRESSION_FAILED_EMPTY_SUMMARY、COMPRESSION_FAILED_INFLATED_TOKEN_COUNT、COMPRESSION_FAILED_MODEL_REQUEST、COMPRESSION_FAILED_PRECOMPACT_BLOCKED、COMPRESSION_FAILED_TOKEN_COUNT_ERROR。可见上下文压缩是一次独立的模型请求，失败会被分类上报，并且在压缩前存在一个“precompact”拦截阶段（例如压缩前需要等待进行中的操作结束）。

另有 `auto_compact_model_threshold_caps`、`systemPromptTokens`、`auto_memory_generation_experiment`、`auto_memory_incremental_generation`、`AGENTS_MD_SIZE_THRESHOLD_REACHED` 等标识，说明自动压缩阈值、系统提示词 token 统计、自动记忆生成与增量记忆、以及项目记忆文件（AGENTS.md 类）体积上限都是显式建模的配置项。

## 5. 权限模型

工具调用存在权限判定环节，字符串中出现 `tool_call_denied`、`available_permission_modes_update` 与政策描述结构，其形如：

```json
{
  "policy": {
    "permissions": "allow",
    "constraints": "Only allow reading 'main.py'.",
    "rationale": "User asked to read main.py"
  }
}
```

即权限判定不仅给出允许/拒绝，还带自然语言形式的约束说明与判定理由。CLI 层面存在 `--dangerously-skip-permissions` 开关跳过该机制。同时存在针对提示注入的防护描述：来自协调者转达的、声称用户已同意或批准的声明不具备用户权威，不可作为授权依据。

## 6. 模型适配层

worker 内部区分 anthropic、openai、openai-responses、openai-compatible、anthropic-compatible 等接口形态，并保留 `systemPromptOverride`、`assistant_tool_use_continuation` 等分支，说明接入了多家模型的协议差异。

结合 `chat.proto` 的 `CustomModelConfig`（name、url、style、provider、type、model、parameters），可确认支持自带密钥接入任意兼容端点。

## 7. 本地状态与缓存

存在名为 `cacheInterceptorV3` 的本地 SQLite 表，字段包括 body、deleteAt、statusCode、statusMessage、headers、etag、cacheControlDirectives，用于按 HTTP 语义缓存与失效。另有 `analysis_log`、`activity log` 与 `privacy.usageStatisticsEnabled` 等统计相关开关。

## 8. 其他可确认的工程细节

`exports dashboard` 生成 Qoder Insights Report（HTML，页脚标注 Generated by Qoder CLI 并链接 qoder.com/cli）。CLI 安装会向 shell 配置写入 PATH（bash 的 `# Added by qodercli install` 与 fish 的 `fish_add_path -a`）。存在一段 pkill 保护逻辑，会识别并拒绝会误杀 Qoder CLI 自身的 pkill 调用，属于防止 agent 自伤的护栏。

## 9. 尚需补齐

agent 主循环的状态机（回合推进、工具调度并发度）、具体提示词全文、工具参数 schema（JSON Schema 定义）、会话与任务的持久化布局，需要基于 CI 产出的结构化代码继续提取；与后端交互的 REST 接口清单（登录、工作区、代码库索引、会话同步）需从主进程产物中系统抽取。
